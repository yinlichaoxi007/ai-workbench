# 资料与脚本存放规则

## 判断顺序

1. 所有项目维护者都要看、且随代码版本走 → 项目仓库的受控目录（`docs/`、`scripts/`、`tools/`）。
2. 只给当事人看，或属于调研、验证、AI 使用过程记录 → 项目 `local/`。
3. 一次性、可随时丢弃 → 当前层级的 `_tmp/`。
4. 跨项目、跨会话长期使用：需要入库并随工作台部署的脚本与内容放本仓库 `content/`；只属于本机的待办、脚本和知识放全局工作台。
5. 个人工作计划、周报月报、总结 → 个人资料目录下的计划总结目录。

## 层级与位置

| 层级 | 位置 | 放什么 | 入库 |
|---|---|---|---|
| 本工作台仓库 | `<仓库路径>` 的 `content/` | 规则、技能、模板、可部署脚本 | 是 |
| 本工作台仓库 | `<仓库路径>` 的 `src/`、`adapters/`、`launchers/`、`tests/`、`docs/` | 工具代码、目标配置、启动器、测试、文档 | 是 |
| 本工作台仓库 | `<仓库路径>/scripts/` | 本仓库自身的维护、部署、校验、打包脚本，不部署 | 是 |
| 本工作台仓库 | `<仓库路径>/local/` | 本机草稿、交付稿、不入库资料 | 否 |
| 本工作台仓库 | `<仓库路径>/_tmp/` | 一次性脚本、验证输出、临时产物 | 否 |
| 全局工作台 | `<全局工作台>/todo/` | 跨会话、跨工具待办 | 否 |
| 全局工作台 | `<全局工作台>/scripts/` | 跨项目可复用本机脚本，按工具或主题分目录；`ai-workbench/` 是仓库 `content/scripts/` 的部署 junction | 否（源在仓库） |
| 全局工作台 | `<全局工作台>/notes/` | 跨项目长期知识，如 AI 工具典型问题库 | 否 |
| 全局工作台 | `<全局工作台>/_tmp/` | 一次性脚本与临时资料 | 否 |
| AI 工具根 | 各工具配置根，路径见 `adapters/targets.json` | 只放部署生成的入口、技能 junction、索引和备份；不放脚本 | 否 |
| 代码项目 | `<项目父级>/<项目名>/docs/`（已有被跟踪的 `doc/` 可沿用） | 设计、方案、接口文档；开发、测试、使用、维护问题库 | 是 |
| 代码项目 | 项目 `scripts/` 或已有 `tools/` | 项目可复用脚本与工具 | 是 |
| 代码项目 | 项目 `local/`（已有 `docs/local/` 可沿用） | 调研与验证记录、AI 使用问题库、仅当事人需要的资料 | 否 |
| 代码项目 | 项目 `local/scripts/` | 项目开发过程专用脚本 | 否 |
| 代码项目 | 项目 `_tmp/`（已有 `dev_tmp/` 可沿用） | 临时脚本和资料 | 否 |
| 个人资料 | `<个人资料目录>/计划总结/<年度>/` | 个人工作计划、周报月报、总结 | 否 |
| 工作资料 | `<工作参考资料目录>/<项目名>/` | 项目外部参考资料、大附件、敏感材料 | 否 |

`<全局工作台>` 的具体路径见机器档案的“全局工作台”。部署写两处：各 AI 工具根只写入口和技能 junction；全局工作台的 `scripts/ai-workbench` 是仓库 `content/scripts/` 的 junction，供 AI 和手工全局调用。规则与技能正文不复制到全局工作台，AI 通过入口中的路径按需读取。

## 项目内目录

- 按名称和内容双重判断：已有 `docs/`、`doc/`、`tools/`、`local/`、`docs/local/`、`dev_tmp/` 等承担同类作用的目录，沿用原名，不另造一套。
- 创建 `local/`、`local/scripts/`、`_tmp/` 前，先把忽略规则写进项目 `.gitignore`。
- `_tmp/` 只放可随时丢弃的内容；临时脚本不要散落在项目根目录，根目录的 `_tmp*` 只作为忽略兜底。
- 不建项目级 TODO 文档。跨会话待办放 `<全局工作台>/todo/`；与其他人协作的事项写进代码注释、issue 或提交说明。
- 项目已有路径索引（`AGENTS.md`、README 或 docs 目录说明）时，同步更新；没有就不新建索引文件。

## 规则、技能与脚本

- 技能自带脚本放 `content/skills/<技能名>/scripts/`，随技能目录一起部署，入库。
- 要随工作台部署、供各工具或手工全局调用的通用脚本放 `content/scripts/`，以零依赖 Node 独立脚本提供，入库；部署时以 junction 安装到 `<全局工作台>/scripts/ai-workbench`，不复制。
- 本仓库自身的维护、部署、校验、打包脚本放 `scripts/`，入库，只在仓库内使用，不部署。
- 与 `build`、`deploy`、GUI 共用的逻辑放 `src/core/`，`scripts/` 与 `content/scripts/` 的脚本只做薄封装。
- 不属于本工作台、不需要入库的跨项目本机脚本放 `<全局工作台>/scripts/` 下的其他子目录；规则只写“全局工作台 `scripts/`”，不写盘符绝对路径。
- `<全局工作台>/scripts/ai-workbench` 是实时 junction，里面的文件就是仓库文件；本机专用脚本放它的同级目录，不要放进 junction。
- 项目规则或技能引用的脚本放项目 `scripts/` 或 `tools/`；仅当事人使用的放项目 `local/scripts/`。
- 一次性脚本放对应层级的 `_tmp/`，任务结束后清理。
- 规则与技能正文不写本机绝对路径；脚本位置用占位符或索引描述。

## 清理

- `_tmp/` 可整目录清理；清理前确认，放入回收站，不直接彻底删除。
- `local/`、`notes/`、`todo/` 不随 `_tmp/` 一起清理。
- 本机档案、密钥、令牌、账号凭据不写入以上任何资料目录。
